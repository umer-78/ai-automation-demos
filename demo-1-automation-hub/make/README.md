# Make.com scenarios

Two scenarios, which fits the Make Free plan (2 active scenarios):

| Blueprint | Trigger | What it does |
| --- | --- | --- |
| `northwind-client-onboarding.blueprint.json` | Custom webhook (new client) | Sync client, then a **router by service** (SEO, Paid Ads, Web Design: checklist and Slack welcome), then the AI brief (saved to Airtable and emailed to the account manager as a draft), a Slack summary and a success log |
| `northwind-client-offboarding.blueprint.json` | Custom webhook (Status = Churned) | Close tasks and archive the client, then a Slack summary and a success log |

```
Webhook ─ Settings ─ Sync client ─ Router ─┬─ [has SEO]        SEO checklist ─ Slack welcome
                          │                ├─ [has Paid Ads]   Paid Ads checklist ─ Slack welcome
                          │                ├─ [has Web Design] Web Design checklist ─ Slack welcome
                          │                └─ Generate brief ─ Slack summary ─ Log success
                          └ error route: Log failure (automation_log + Slack alert) ─ Skip
                                          └ if the hub API is down: post straight to Slack
```

Every API module has an error route. It writes the failure to `automation_log` through
`/api/automation/log`, which also sends the Slack alert. If the hub itself is unreachable, a
nested route posts directly to Slack, so a failure is never silent.

## Import

1. In Make: **Scenarios**, **Create a new scenario**, the **⋯** menu, **Import blueprint**, pick a file.
2. Click the webhook module, **Add** a new webhook, copy its URL.
3. Open module 2 (**Settings**) and set `api_base` (your deployed hub URL),
   `automation_key` (same value as `AUTOMATION_API_KEY`) and `slack_webhook`.
4. Click **Run once**, then send a test client so Make learns the data structure:
   ```bash
   curl -X POST "$MAKE_WEBHOOK_URL" -H "Content-Type: application/json" -d '{
     "event": "client.created", "name": "Coastal Coffee Roasters",
     "website": "https://coastalcoffee.example", "industry": "Food & beverage",
     "services": ["SEO", "Paid Ads"], "manager": "Elena Rossi",
     "manager_email": "elena@northwind-digital.example", "run_id": "test000001"}'
   ```
5. Turn the scenario on. Put the webhook URLs in `MAKE_ONBOARDING_WEBHOOK_URL` and
   `MAKE_OFFBOARDING_WEBHOOK_URL` so the dashboard form and the Airtable bridge use Make.

**Prove the error route:** send the same payload with `"simulate_failure": true` (or tick
*Simulate Failure* on an Airtable row). The brief step returns HTTP 500, the error route logs
the failure and Slack gets the alert.

Values are sent to the hub as query-string parameters, which Make URL-encodes, so client
names with quotes or emoji never break a JSON body. The hub returns a ready-made
`slack_payload` for every Slack post for the same reason.

## Rebuild / validate

The blueprints are generated by `build_blueprints.py`. The backend test suite runs both
blueprints end to end against the real API (`backend/tests/test_make_blueprints.py`).

```bash
python make/build_blueprints.py          # regenerate
python make/build_blueprints.py --check  # CI: fail if the JSON is out of date
```

Note: Make renamed the *Ignore* directive to *Skip* in May 2026; blueprints still use the
`builtin:Ignore` module id, which imports as Skip.
